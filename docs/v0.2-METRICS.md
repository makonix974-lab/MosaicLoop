## Output validation

Frame comparison at 50% duration (101.35 s into the video):

| Metric | Result |
|---|---|
| Mean absolute pixel difference | **0.454 / 255** |
| Max absolute pixel difference | 192 / 255 (single-pixel encoder noise) |
| Pixels within ±8/255 of v0.1 | **99.18 %** |
| Output duration | **202.70 s** (identical to v0.1) |
| Output file size | ~55 MB (h264, 30 fps) |

A mean diff of 0.454/255 is well under the 5/255 threshold we set for
"visually equivalent under typical encoder non-determinism." The 99.18 %
near-match figure is what we'd expect from two h264 encodes of the same
filter graph — variations are encoder noise, not content.

## What we shipped

- **Reliability**: the freeze that motivated the refactor is impossible by
  construction now — stderr is always drained.
- **Speed (cold)**: collapsed pipeline removes ~50% of FFmpeg work
  (no apply_offsets stage = no double-encoding the proxy).
- **Speed (warm)**: session cache makes re-runs trivial (3.1× faster).
- **Disk**: zero intermediate files. On big rushes this is gigabytes saved.
- **Maintainability**: 60% less code, three deps, real tests with real
  fixtures that catch real bugs.
- **Honesty**: README and PROJECT.md describe what the tool does, not
  what it might do someday.

The v0.2 output is visually equivalent to v0.1 on the production rushes,
so existing consumers of the tool won't notice the refactor — except for
the speed and the absence of hangs.
